# 터미널에서 서버 실행

PowerShell에서 서버를 띄우는 방법입니다. JDK 21과 Docker Desktop이 설치되어 있어야 합니다. 준비 순서는 [설치 가이드](설치-가이드.md)를 따릅니다.

서비스마다 JVM이 하나씩 생깁니다. 아래 명령은 힙을 512MB로 제한합니다.

## 1. 인프라

저장소 루트에서 실행합니다. Postgres, Redis, RabbitMQ, Kafka, ZooKeeper가 여기 포함됩니다.

```powershell
docker compose up -d
```

## 2. 환경변수

`coliving-platform-config`의 `dev` 설정에 값이 없는 변수만, 그 서버를 띄우는 PowerShell 창에서 지정합니다. 그 창을 닫으면 값은 사라집니다. 값은 문서에 적지 않습니다.

```powershell
$env:NAVER_CLIENT_ID = "네이버 클라이언트 ID"
$env:NAVER_CLIENT_SECRET = "네이버 시크릿"
$env:GOOGLE_CLIENT_ID = "구글 클라이언트 ID"
$env:GOOGLE_CLIENT_SECRET = "구글 시크릿"
$env:KAKAOPAY_SECRET_KEY = "카카오페이 시크릿"
$env:PORTONE_STORE_ID = "포트원 상점 ID"
$env:PORTONE_API_SECRET = "포트원 시크릿"
$env:GEMINI_API_KEY = "Gemini API 키"
```

| 변수 | 쓰는 서버 | 용도 |
|------|-----------|------|
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 사용자 서비스 | 네이버 로그인 |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | 사용자 서비스 | 구글 로그인 |
| `KAKAOPAY_SECRET_KEY` | 계약 서비스 | 카카오페이 |
| `PORTONE_STORE_ID`, `PORTONE_API_SECRET` | 계약 서비스 | 포트원 본인인증 |
| `GEMINI_API_KEY` | 커뮤니티 서비스 | FAQ 봇 |

변수를 넣은 뒤에 그 창에서 `bootRun`을 실행합니다.

## 3. 공통 서버

서비스마다 터미널을 하나 엽니다. `bootRun`은 그 창을 점유합니다. 종료는 해당 창에서 `Ctrl+C`입니다.

Eureka를 먼저 띄웁니다.

```powershell
cd services\eureka-server
.\gradlew.bat bootRun "-Dspring-boot.run.jvmArguments=-Xmx512m"
```

http://localhost:8761 이 열리면 Config Server를 띄웁니다. Config Server는 `coliving-platform-config` 저장소의 `dev` 브랜치를 받으므로 GitHub에 접속할 수 있어야 합니다.

```powershell
cd services\config-server
.\gradlew.bat bootRun "-Dspring-boot.run.jvmArguments=-Xmx512m"
```

그다음 API Gateway를 띄웁니다.

```powershell
cd services\api-gateway
.\gradlew.bat bootRun "-Dspring-boot.run.jvmArguments=-Xmx512m"
```

## 4. 업무 서버

Config Server가 뜬 뒤에 필요한 서비스만 띄웁니다. 비밀값이 필요한 서비스는 그 창에서 환경변수를 먼저 넣습니다. 폴더로 이동한 뒤 명령은 모두 같습니다.

예약 서비스 예입니다.

```powershell
$env:DB_PASSWORD = "데이터베이스 비밀번호"
cd services\reservation-service
.\gradlew.bat bootRun "-Dspring-boot.run.jvmArguments=-Xmx512m"
```

다른 업무 서버는 같은 방식으로 실행합니다.

```powershell
.\gradlew.bat bootRun "-Dspring-boot.run.jvmArguments=-Xmx512m"
```

| 순서 | 폴더 | 포트 |
|------|------|------|
| 1 | `services\eureka-server` | 8761 |
| 2 | `services\config-server` | 8888 |
| 3 | `services\api-gateway` | 8081 |
| 4 | `services\user-service` | 8082 |
| 4 | `services\property-service` | 8083 |
| 4 | `services\community-service` | 8084 |
| 4 | `services\reservation-service` | 8085 |
| 4 | `services\dashboard-service` | 8086 |
| 4 | `services\document-service` | 8087 |
| 4 | `services\contract-service` | 8089 |

업무 서버는 서로 순서가 없습니다. 작업 중인 서비스만 켜도 됩니다.

## 5. 프론트

프론트도 화면마다 터미널을 하나 엽니다. Node.js가 설치되어 있어야 합니다. 처음 한 번은 의존성을 설치합니다. API 주소는 각 폴더의 `.env`에 `VITE_BACKEND_API_BASE_URL=http://localhost:8081`로 들어 있습니다. 게이트웨이가 8081에서 떠 있어야 화면의 API 호출이 동작합니다.

사용자 화면입니다. 포트는 Vite 기본값 5173입니다.

```powershell
cd frontends\user-web
npm i
npm run dev
```

관리자 화면입니다. 포트는 3000입니다.

```powershell
cd frontends\admin-web
npm i
npm run dev
```

| 화면 | 폴더 | 주소 |
|------|------|------|
| 사용자 | `frontends\user-web` | http://localhost:5173 |
| 관리자 | `frontends\admin-web` | http://localhost:3000 |

`npm i`는 의존성이 없을 때만 실행하면 됩니다. 종료는 해당 창에서 `Ctrl+C`입니다.

## 6. 확인

게이트웨이까지 띄운 뒤 브라우저에서 http://localhost:8761 을 엽니다. 등록된 서비스 이름이 `UP`이면 기동이 끝난 것입니다.

## 번외. 다른 PC의 Docker에 연결

Kafka와 ZooKeeper만 이 PC에서 켜고, 나머지 Docker는 `192.168.0.0` PC에서 켤 때입니다. 프로젝트 파일은 수정하지 않습니다. 환경변수는 그 서버를 띄우는 PowerShell 창에서만 지정하고, 창을 닫으면 사라집니다. 설정 파일의 `localhost`보다 이 값이 우선합니다.

이 PC:

```powershell
docker compose up -d zookeeper kafka
```

`192.168.0.0` PC:

```powershell
docker compose up -d postgres pgvector mongodb redis rabbitmq elasticsearch kibana prometheus grafana
```

`192.168.0.0`의 방화벽에서 `5432`, `5433`, `27017`, `6379`, `5672`, `9200`을 엽니다. Kafka는 이 PC의 `localhost:9092`를 그대로 씁니다. Eureka, gRPC, 게이트웨이, 프론트 주소도 바꾸지 않습니다.

RabbitMQ를 쓰는 창에는 공통으로 넣습니다. Config Server도 포함합니다.

```powershell
$env:SPRING_RABBITMQ_HOST = "192.168.0.0"
```

서비스 창에는 해당 주소만 더 넣습니다.

```powershell
# 사용자 서비스
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://192.168.0.0:5432/user_service"
$env:SPRING_DATA_REDIS_HOST = "192.168.0.0"

# 매물 서비스
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://192.168.0.0:5432/property_service"

# 계약 서비스
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://192.168.0.0:5432/contract_service"
$env:SPRING_DATA_REDIS_HOST = "192.168.0.0"

# 커뮤니티 서비스
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://192.168.0.0:5433/community_service"
$env:SPRING_MONGODB_URI = "mongodb://192.168.0.0:27017/community_service"
$env:SPRING_DATA_REDIS_HOST = "192.168.0.0"

# 예약 서비스
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://192.168.0.0:5432/reservation_service"

# 문서 서비스
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://192.168.0.0:5432/document_service"

# 대시보드 서비스
$env:SPRING_ELASTICSEARCH_URIS = "http://192.168.0.0:9200"
```

변수를 넣은 뒤에 그 창에서 `bootRun`을 실행합니다. 데이터베이스 내용은 PC마다 따로라서, `192.168.0.0`의 데이터베이스는 그 PC에서 만든 데이터만 있습니다.
