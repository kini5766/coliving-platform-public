# 배포 가이드

Argo CD로 `k8s/base`를 클러스터에 올리는 순서입니다. 작업 디렉터리는 저장소 루트입니다.

Secret `coliving-infra`, `coliving-app`은 Git에 올리지 않습니다. 샘플만 커밋하고, 값이 채워진 파일은 클러스터에 직접 적용합니다. Argo CD Sync는 이 Secret을 만들거나 덮어쓰지 않습니다.

## 1. Secret 파일 만들기

처음 받는 클론에는 샘플만 있습니다.

```powershell
Copy-Item k8s\base\platform\coliving-infra.yaml.sample k8s\base\platform\coliving-infra.yaml
Copy-Item k8s\base\platform\coliving-app.yaml.sample k8s\base\platform\coliving-app.yaml
```

두 파일의 `stringData`를 배포 값으로 채웁니다. 빈 값 그대로 적용하면 Postgres와 RabbitMQ가 뜨지 않습니다.

`coliving-infra.yaml`

| 키 | 쓰는 곳 |
|---|---|
| `postgres-user`, `postgres-password` | Postgres, pgvector |
| `rabbitmq-user`, `rabbitmq-password` | RabbitMQ. `guest`는 다른 파드에서 접속이 거절됩니다. |
| `redis-password` | Redis. 빈 문자열이면 AUTH를 하지 않습니다. |
| `grafana-admin-user`, `grafana-admin-password` | Grafana |

Postgres와 Redis 비밀번호는 브라우저에서 만듭니다. 생성 값은 브라우저 안에만 있고 사이트 서버로 전송되지 않습니다. 만든 비밀번호만 Secret에 넣습니다. 페이지에 같이 나오는 SQL, `requirepass`, ACL 명령, 접속 URL은 사용하지 않습니다.

Postgres 비밀번호는 [PostgreSQL Password Generator](https://www.sethserver.com/postgresql/postgresql-strong-password-generator.html)에서 `regen`을 누른 뒤 `copy`로 비밀번호만 복사합니다. `coliving-infra.yaml`의 `postgres-password`에 붙여 넣습니다. `postgres-user`는 `postgres`로 둡니다. 준비 상태 검사가 `pg_isready -U postgres`입니다. 데이터 디스크가 비어 있는 첫 기동에서 이 계정이 만들어집니다.

Redis 비밀번호는 [Redis Password Generator](https://www.sethserver.com/security/redis-password-generator.html)에서 만듭니다. **URL-safe only**를 켠 뒤 비밀번호만 복사해 `redis-password`에 넣습니다. 이 값이 있으면 Redis는 AUTH를 요구하고, 앱은 Secret의 이 값으로 접속합니다.

Windows에 `openssl`이 없으면 설치합니다.

```powershell
winget install --id ShiningLight.OpenSSL.Light -e
```

설치만으로는 `openssl`이 경로에 없습니다. 사용자 환경 변수 `Path`에 설치 폴더를 추가합니다.

```powershell
[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";C:\Program Files\OpenSSL-Win64\bin", "User")
```

추가한 뒤에는 새 PowerShell을 엽니다. `openssl version`이 버전을 출력하면 아래 명령을 실행합니다.

`rabbitmq-password`와 `grafana-admin-password`는 각각 다른 `openssl rand -hex 24` 결과를 넣습니다.

```powershell
openssl rand -hex 24
```

YAML에 넣을 때 값은 큰따옴표로 감쌉니다. 비밀번호에 `"`나 `\`가 있으면 `regen`으로 다시 만듭니다.

`coliving-app.yaml`

| 키 | 쓰는 곳 |
|---|---|
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 네이버 로그인 |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | 구글 로그인 |
| `KAKAOPAY_SECRET_KEY`, `KAKAOPAY_CID` | 카카오페이 |
| `MAIL_USERNAME`, `MAIL_APP_PASSWORD` | 계약 안내 메일 |
| `PORTONE_STORE_ID`, `PORTONE_API_SECRET` | 포트원 |
| `GEMINI_API_KEY` | 커뮤니티 FAQ 봇 |
| `USER_CRYPTO_KEY` | 회원 정보 AES-256-GCM 봉투 암호화 |
| `COMMUNITY_CRYPTO_KEY` | 비회원 연락처 AES-256-GCM |
| `JWT_PUBLIC_KEY`, `JWT_PRIVATE_KEY` | 액세스 토큰 서명 |

`k8s/base/platform/config.yaml`의 `MAIL_ENABLED`는 `false`입니다. 메일을 보내려면 `MAIL_USERNAME`과 `MAIL_APP_PASSWORD`를 채운 뒤 `MAIL_ENABLED`를 `true`로 바꿉니다. `USER_WEB_URL`은 메일 버튼이 여는 사용자 화면입니다.

`USER_CRYPTO_KEY`와 `COMMUNITY_CRYPTO_KEY`는 각각 다른 `openssl rand -base64 32` 결과를 넣습니다. 값은 32바이트를 표준 Base64로 적은 것입니다.

```powershell
openssl rand -base64 32
```

`JWT_PRIVATE_KEY`와 `JWT_PUBLIC_KEY`는 EC P-256 키입니다. `keystore/secret/`에 키 파일을 만든 뒤, 파일 내용을 `coliving-app.yaml`에 넣습니다.

`keystore/secret/`은 `.gitignore`에 있습니다. `jwt-private.pem`과 `jwt-public.pem`은 Git 저장소에 올리지 마세요.

```powershell
New-Item -ItemType Directory -Force keystore\secret | Out-Null
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out keystore\secret\jwt-private.pem
openssl pkey -pubout -in keystore\secret\jwt-private.pem -out keystore\secret\jwt-public.pem
```

개인키 첫 줄은 `-----BEGIN PRIVATE KEY-----`, 공개키 첫 줄은 `-----BEGIN PUBLIC KEY-----`입니다. YAML에는 이렇게 적습니다.

```yaml
JWT_PRIVATE_KEY: |
  -----BEGIN PRIVATE KEY-----
  ...
  -----END PRIVATE KEY-----
JWT_PUBLIC_KEY: |
  -----BEGIN PUBLIC KEY-----
  ...
  -----END PUBLIC KEY-----
```

`coliving-infra.yaml`과 `coliving-app.yaml`은 `.gitignore`에 있습니다. `git status`에 나오면 안 됩니다.

## 2. Secret을 클러스터에 적용

네임스페이스를 만든 뒤 Secret을 적용합니다. Secret 매니페스트의 네임스페이스는 `coliving`입니다.

```powershell
kubectl create namespace coliving --dry-run=client -o yaml | kubectl apply -f -
kubectl apply -f k8s\base\platform\coliving-infra.yaml
kubectl apply -f k8s\base\platform\coliving-app.yaml
```

값을 바꾼 뒤에는 같은 명령을 다시 실행합니다. 그 다음 해당 값을 읽는 파드를 재시작합니다. 이미 떠 있는 프로세스는 Secret 변경을 다시 읽지 않습니다.

## 3. 브랜치를 올린 뒤 Argo CD에 등록

Application `coliving-platform`은 `https://github.com/ibm05-team-3/coliving-platform.git`의 `main` 브랜치에서 `k8s/base`를 읽습니다. `main`에 반영된 매니페스트를 5장에서 Sync합니다. 자동 Sync는 없습니다. 4장에서 앱 이미지를 올린 뒤에 Sync합니다.

Argo CD가 없으면 `AppProject`와 `Application`을 만들 수 없습니다. 한 번 설치합니다.

```powershell
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
kubectl wait --namespace argocd --for=condition=Ready pod --all --timeout=300s
```

`schema.sql`은 `k8s/base` 밖에 있습니다. Argo CD 3는 Application 매니페스트의 `kustomize.buildOptions`를 받지 않습니다. 같은 옵션을 ConfigMap `argocd-cm`에 넣고 repo-server를 재시작합니다.

```powershell
'{"data":{"kustomize.buildOptions":"--load-restrictor LoadRestrictionsNone"}}' | Set-Content -Encoding ascii $env:TEMP\argocd-cm.json
kubectl -n argocd patch cm argocd-cm --type merge --patch-file $env:TEMP\argocd-cm.json
kubectl -n argocd rollout restart deploy/argocd-repo-server
kubectl -n argocd rollout status deploy/argocd-repo-server
```

저장소는 비공개입니다. 인증이 없으면 Sync가 `Repository not found`로 끝납니다. GitHub App `coliving-argocd`로 읽기 권한을 줍니다. 개인키 파일과 아래 Secret은 `keystore/secret/`에 둡니다.

`keystore/secret/`은 `.gitignore`에 있습니다. `coliving-argocd.pem`과 `repo-coliving-platform.yaml`은 Git 저장소에 올리지 마세요.

조직 `ibm05-team-3`의 Settings → Developer settings → GitHub Apps에서 앱을 만듭니다. 조직 소유자만 만들 수 있습니다.

| 항목 | 값 |
|---|---|
| GitHub App name | `coliving-argocd`. GitHub 전체에서 하나뿐이어야 합니다. 이미 있으면 `coliving-platform-argocd` |
| Homepage URL | `https://github.com/ibm05-team-3/coliving-platform` |
| Webhook | Active 해제 |
| Repository permissions → Contents | Read-only |
| Where can this GitHub App be installed? | Only on this account |

General 페이지의 App ID를 적어둡니다. Credentials → Key pairs → New key를 누르면 `.pem`이 내려받아집니다. 받은 파일은 `keystore/secret/coliving-argocd.pem`으로 저장합니다. GitHub는 이 개인키를 다시 보여주지 않습니다. 첫 줄은 `-----BEGIN RSA PRIVATE KEY-----`입니다. Client secrets는 만들지 않습니다. SSH 키나 JWT 키와 다른 파일입니다.

`keystore/secret/`은 `.gitignore`에 있습니다. `coliving-argocd.pem`은 Git 저장소에 올리지 마세요.

Install App에서 `ibm05-team-3`에 설치합니다. Only select repositories를 고르고 `ibm05-team-3/coliving-platform`만 선택합니다. 설치 뒤 주소의 숫자가 Installation ID입니다.

`https://github.com/organizations/ibm05-team-3/settings/installations/<Installation ID>`

같은 조직의 다른 저장소는 이 설치에 나중에 추가합니다. 앱을 새로 만들지 않습니다. App ID, Installation ID, 개인키는 그대로 두고 Secret만 저장소 URL을 바꿔 하나 더 만듭니다. `k8s/argocd/project.yaml`의 `sourceRepos`에도 그 주소를 넣습니다. 다른 GitHub 계정의 저장소는 앱을 새로 만듭니다. 이 조직에는 다른 GitHub App도 나중에 설치할 수 있습니다.

`keystore/secret/repo-coliving-platform.yaml`을 만듭니다. `url`은 `k8s/argocd/application.yaml`의 `repoURL`과 같아야 합니다. `githubAppPrivateKey`에는 `keystore/secret/coliving-argocd.pem` 전체를 넣습니다.

`keystore/secret/`은 `.gitignore`에 있습니다. `repo-coliving-platform.yaml`은 Git 저장소에 올리지 마세요.

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: repo-coliving-platform
  namespace: argocd
  labels:
    argocd.argoproj.io/secret-type: repository
stringData:
  type: git
  url: https://github.com/ibm05-team-3/coliving-platform.git
  githubAppID: "<App ID>"
  githubAppInstallationID: "<Installation ID>"
  githubAppPrivateKey: |
    -----BEGIN RSA PRIVATE KEY-----
    ...
    -----END RSA PRIVATE KEY-----
```

```powershell
kubectl apply -f keystore\secret\repo-coliving-platform.yaml
```

프로젝트와 Application을 등록합니다. Application 매니페스트에는 `kustomize.buildOptions`를 넣지 않습니다.

```powershell
kubectl apply -f k8s\argocd\project.yaml
kubectl apply -f k8s\argocd\application.yaml
```

## 4. 앱 이미지 CI

앱 Deployment는 `ghcr.io/ibm05-team-3/<서비스>:latest`를 받습니다. 이미지를 만들어 GHCR에 올리는 워크플로는 `.github/workflows/images.yaml`입니다. 이 파일이 `main`에 있으면 GitHub Actions가 빌드하고 push합니다.

조직 Settings → Actions → General → Workflow permissions가 읽기 전용이면 `packages: write`가 거절됩니다. Read and write permissions를 고릅니다.

Actions 실행이 성공하면 패키지 목록에 이미지가 있습니다.

`https://github.com/orgs/ibm05-team-3/packages`

`GITHUB_TOKEN`으로 처음 만든 패키지는 비공개입니다. 클러스터가 로그인 없이 받으면 GHCR가 403을 반환하고 파드는 `ImagePullBackOff`가 됩니다. 패키지 페이지의 Package settings에서 Change package visibility를 Public으로 바꿉니다. 서비스마다 한 번씩 합니다.

비공개로 두려면 `read:packages` 권한이 있는 Personal Access Token으로 pull Secret을 만듭니다. 토큰은 `keystore/secret/ghcr-pull.token`에 적어둡니다.

`keystore/secret/`은 `.gitignore`에 있습니다. `ghcr-pull.token`은 Git 저장소에 올리지 마세요.

```powershell
kubectl create secret docker-registry ghcr-pull -n coliving --docker-server=ghcr.io --docker-username=<GitHub 사용자> --docker-password=<PAT>
'{"imagePullSecrets":[{"name":"ghcr-pull"}]}' | Set-Content -Encoding ascii $env:TEMP\ghcr-pull.json
kubectl patch serviceaccount default -n coliving --type merge --patch-file $env:TEMP\ghcr-pull.json
```

`imagePullPolicy`가 `Always`이므로 이미 떠 있는 파드는 새 `latest`를 스스로 받지 않습니다. CI가 끝난 뒤 해당 파드를 지웁니다.

```powershell
kubectl delete pod -n coliving -l app.kubernetes.io/name=eureka-server
```

## 5. Sync

4장에서 Docker 이미지를 ghcr.io/ibm05-team-3/<서비스>:latest 이름으로 GHCR에 업로드했다면, 이제 Argo CD에 변경된 이미지를 적용하도록 Sync를 요청합니다.

현재 자동 Sync는 비활성화되어 있으므로 명령어를 실행해 수동으로 배포해야 합니다.

아래 명령어는 Argo CD가 관리하는 coliving-platform 애플리케이션에 Sync를 요청하는 작업입니다.

```powershell
'{"operation":{"sync":{}}}' | Set-Content -Encoding ascii $env:TEMP\coliving-sync.json
kubectl patch application coliving-platform -n argocd --type merge --patch-file $env:TEMP\coliving-sync.json
```

다음과 같은 문제가 있으면 파드가 정상적으로 실행되지 않고 ImagePullBackOff 상태가 될 수 있습니다.
- GHCR에 해당 이미지가 업로드되지 않은 경우
- 이미지 이름이나 태그가 잘못된 경우
- GHCR 이미지에 접근할 권한이 없는 경우

## 6. 첫 관리자

운영 프로파일은 관리자 계정을 만들지 않습니다. 개발 프로파일의 `InitialDataLoader`만 `admin@naver.com`을 넣습니다. 배포의 `SPRING_PROFILES_ACTIVE`는 `prod`입니다.

첫 관리자 한 명은 `user_service` 데이터베이스에 직접 넣습니다. 5장 Sync로 `users`, `user_roles`, `user_email_accounts`가 생긴 뒤에 합니다. 같은 이메일이 이미 있으면 다시 넣지 않습니다. 두 번째 관리자부터는 관리 화면에서 만듭니다.

비밀번호는 평문으로 넣지 않습니다. `user_email_accounts.password`는 `{bcrypt}`로 시작하는 해시입니다. 이 SQL과 평문 비밀번호는 Git에 올리지 않습니다.

해시를 만듭니다. `admin:` 뒤를 복사하고 앞에 `{bcrypt}`를 붙입니다. `$2y$`는 그대로 둡니다.

```powershell
docker run --rm httpd:2.4-alpine htpasswd -nbB admin "여기에-비밀번호"
```

이메일은 소문자로 넣습니다. `postgres-0`이 뜬 뒤 `user_service`에 접속합니다.

```powershell
kubectl exec -n coliving -it postgres-0 -- psql -U postgres -d user_service
```

`<이메일>`과 `<해시>`만 바꾼 뒤 실행합니다. `<해시>`에는 `{bcrypt}$2y$...` 전체를 넣습니다.

```sql
INSERT INTO users (enabled, account_non_locked, created_at, updated_at)
VALUES (TRUE, TRUE, NOW(), NOW())
RETURNING id;

INSERT INTO user_roles (user_id, role)
VALUES (<방금 나온 id>, 'ADMIN');

INSERT INTO user_email_accounts (user_id, email, password, created_at, updated_at)
VALUES (<같은 id>, '<이메일>', '<해시>', NOW(), NOW());
```

로그인에 계약서 자동완성 행은 필요 없습니다. `contract_autocomplete`의 이메일은 애플리케이션이 암호화해 저장합니다.

## 7. 도메인 연결

도메인을 EC2에 연결하는 절차는 [AWS 가비아 도메인 연결 가이드](AWS-가비아-도메인-연결-가이드.md)에 있습니다.

저장소에 설정된 도메인은 `darkhanmarie.site`입니다. 구매한 도메인이 다르면 그 이름으로 바꿉니다. 아래 표의 `example.com`은 구매한 도메인 예시입니다. `darkhanmarie.site`를 `example.com`으로 바꾸듯이, 아래 파일의 같은 이름도 구매한 도메인으로 맞춥니다.

- `k8s/base/platform/ingress.yaml`의 호스트
- `k8s/base/platform/config.yaml`의 `FRONTEND_URL`, `USER_WEB_URL`, `APP_CORS_ALLOWED_ORIGINS`, `NAVER_REDIRECT_URI`, `GOOGLE_REDIRECT_URI`, `COMMUNITY_CHAT_ALLOWED_ORIGINS`
- `.github/workflows/images.yaml`의 `build-args`
- `frontends/user-web/Dockerfile`과 `frontends/admin-web/Dockerfile`의 `VITE_` 기본값

이름을 바꾼 뒤 이미지를 다시 빌드하고 Sync합니다.

5장 Sync로 Ingress가 생긴 뒤에 DNS를 연결합니다. 실제 도메인도 표와 같은 형태로 `k8s/base/platform/ingress.yaml`의 `host`에 적습니다. 도메인 등록처 DNS가 그 이름을 Ingress 컨트롤러로 보냅니다. `host`에는 IP를 적지 않습니다.

| 접속 주소 | 등록처에 넣는 이름 | 서비스 |
|---|---|---|
| `user.example.com` | `user` | user-web |
| `admin.example.com` | `admin` | admin-web |
| `api.example.com` | `api` | api-gateway |
| `eureka.example.com` | `eureka` | Eureka |
| `grafana.example.com` | `grafana` | Grafana |
| `kibana.example.com` | `kibana` | Kibana |
| `prometheus.example.com` | `prometheus` | Prometheus |
| `rabbitmq.example.com` | `rabbitmq` | RabbitMQ |

등록처가 전체 이름을 요구하면 `user.example.com`처럼 적습니다. 루트 도메인만 받는 화면이면 이름 칸에는 `user`만 적습니다. `*.example.com` 와일드카드 레코드 하나면 위 이름을 한 번에 덮습니다. 루트 `example.com`은 Ingress가 쓰지 않습니다.

매니페스트는 Ingress 컨트롤러를 설치하지 않습니다. 클러스터에 컨트롤러가 있어야 주소가 나옵니다. Sync로 만든 Ingress 주소를 확인합니다.

```powershell
kubectl get ingress -n coliving coliving
```

`ADDRESS`가 비어 있으면 컨트롤러 Service를 봅니다.

```powershell
kubectl get svc -A
```

`EXTERNAL-IP` 값으로 레코드 종류를 정합니다.

- IPv4 주소이면 A 레코드입니다. 값은 그 IP입니다.
- `xxxx.elb.amazonaws.com`처럼 호스트 이름이면 CNAME입니다. 값은 그 호스트 이름입니다.
- `<pending>`이면 LoadBalancer가 아직 없습니다. 주소가 나온 뒤에 레코드를 만듭니다.

등록처 DNS에 레코드를 저장한 뒤 확인합니다. 반영에는 시간이 걸릴 수 있습니다.

아래 명령어는 `nslookup`으로 도메인 이름이 어떤 주소로 응답하는지 조회하는 작업입니다.

```powershell
nslookup user.example.com
nslookup admin.example.com
nslookup api.example.com
```

응답이 Ingress 주소와 같으면 브라우저에서 `http://user.example.com`, `http://admin.example.com`, `http://api.example.com`을 엽니다. HTTPS는 8장의 Let’s Encrypt 발급 뒤 열립니다. 80번 포트가 Ingress 컨트롤러까지 열려 있어야 합니다.

구매한 도메인으로 맞출 파일은 이 장 앞의 목록과 같습니다. 이름을 바꾼 뒤 이미지를 다시 빌드하고 Sync합니다.

## 8. Let’s Encrypt 인증서

cert-manager가 Let’s Encrypt 인증서를 발급하고 Ingress에 연결합니다. 아래 주소는 샘플 도메인 `example.com`입니다. `k8s/base/platform/ingress.yaml`의 `host`와 같은 이름을 사용합니다.

발급 전에 7장의 DNS가 끝나 있어야 합니다. Let’s Encrypt는 `http://호스트/.well-known/acme-challenge/`로 소유를 확인하므로 인터넷에서 80번 포트가 열려 있어야 합니다.

cert-manager는 이 저장소 매니페스트에 없습니다. 클러스터에 한 번 설치합니다.

```powershell
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.21.3/cert-manager.yaml
kubectl wait --namespace cert-manager --for=condition=Ready pod --all --timeout=180s
```

발급자는 ClusterIssuer입니다. `letsencrypt-prod.yaml`은 `k8s/base`에 넣지 않습니다. Kustomize가 네임스페이스 `coliving`을 붙입니다. 아래 내용을 `keystore/secret/letsencrypt-prod.yaml`로 저장합니다. `email`은 만료 알림을 받을 주소로 바꾼 뒤 그 파일을 적용합니다.

`keystore/secret/`은 `.gitignore`에 있습니다. `letsencrypt-prod.yaml`은 Git 저장소에 올리지 마세요.

```yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: you@example.com
    privateKeySecretRef:
      name: letsencrypt-prod-account
    solvers:
      - http01:
          ingress:
            class: nginx
```

```powershell
kubectl apply -f keystore\secret\letsencrypt-prod.yaml
```

처음 확인할 때는 `server`를 `https://acme-staging-v02.api.letsencrypt.org/directory`로 두고 이름을 `letsencrypt-staging`으로 합니다. 연습용 인증서는 브라우저가 신뢰하지 않습니다. 발급이 되면 운영 발급자로 바꿉니다.

Ingress를 Sync하면 cert-manager가 `Certificate`를 만들고 Secret `coliving-tls`에 인증서를 저장합니다. 이 Secret은 Git에 올리지 않습니다. 443번 포트가 Ingress 컨트롤러까지 열려 있어야 합니다. 만료 전에 cert-manager가 갱신합니다.

```powershell
kubectl get certificate -n coliving
kubectl describe certificate coliving-tls -n coliving
```

`READY`가 `True`이면 `https://user.example.com`, `https://admin.example.com`, `https://api.example.com`을 엽니다.
